# Звіт до лабораторної роботи № 2

## 1. Тема, номер і варіант
Класи, record і інкапсуляція в Java-проєкті. Предметна область: Каталог фільмів.
Варіант: 8. ОС: Windows <версія>.

## 2. Мета роботи
Замінити рядкові записи й паралельні змінні з ЛР № 1 класом `Movie`, перенести
валідацію в конструктор, додати `fromCsv` і `record YearRating`, зберегти зовнішню
поведінку та перевірити її тестами.

## 3. Стан до і після цієї роботи
| Було (ЛР № 1, `Main.main`) | Стало (ЛР № 2) |
|---|---|
| `String line`, `split(";", -1)`, `fields[0..4]` | `Movie.fromCsv(line)` |
| `List<String> validRecords` (лише назви), `ratingSum`, `longestMinutes`, `oldestYear` | `List<Movie>` + `CatalogService.summarize` |
| перевірки в циклі (`if ... continue`) | конструктор `Movie` |
| звіт збирається в `Main` через `report +=` | `CatalogService.buildReport` |
| окремі змінні підсумку | `record YearRating` |

## 4. Клас-сутність
Поля: `title`, `director`, `year`, `minutes`, `rating` (private final).
Інваріанти: назва/режисер не null і не порожні; рік > 0; хвилини > 0; рейтинг у [0; 10], скінченний.
Методи читання: `getTitle`, `getDirector`, `getYear`, `getMinutes`, `getRating`. Сеттерів немає (стан незмінний).
`toString` форматується через `Locale.ROOT`.
Обґрунтування: рік і тривалість без нуля — нуль не має предметного сенсу (так було й у ЛР № 1). Єдина зміна поведінки: у ЛР № 1 перевірявся лише рейтинг < 0; за таблицею варіантів ЛР № 2 рейтинг має бути «в діапазоні», тому додано верхню межу 10 (і відхилення NaN/Infinity). На даних `data/input.csv` це не змінює результат.

## 5. Фабричний метод і record
`fromCsv`: порожній рядок, 5 полів (`split(";", -1)`), `NumberFormatException` → `IllegalArgumentException`.
Інваріанти перевіряє лише конструктор — правила не дублюються.
`YearRating(count, averageRating, longestMinutes, oldestYear)` — незмінний підсумок із перевіркою у компактному конструкторі.

## 6. Тестування
Нові: `MovieTest`, `YearRatingTest`, `CatalogServiceTest` (містить тест `reportMatchesLab01Output` з даними ЛР № 1). Перенесено `MainTest` (змінено лише очікувану версію 1.0.0 → 1.1.0).
Позитивні: коректний конструктор і fromCsv, українські символи. Граничні: рейтинг 0 і 10, рік 1, тривалість 1.
Негативні: null, порожній текст, 0 і від'ємні значення, NaN, Infinity, неправильна кількість полів, нечислове поле.
Перенесені тести ЛР № 1: `programShouldProcessValidRecords`, `programShouldCreateReport`, `versionOptionShouldWork` (версію оновлено до 1.1.0).

## 1. Мета роботи

Метою лабораторної роботи є створення консольного Java-проєкту з використанням Maven, реалізація базової обробки даних із CSV-файлу, перевірка коректності вхідних даних, написання модульних тестів, виконання статичного аналізу та налаштування автоматичної перевірки проєкту за допомогою GitHub Actions.

## 2. Постановка задачі

Необхідно реалізувати консольну програму для обробки каталогу фільмів.

Для кожного фільму використовуються такі поля:

* `title` — назва фільму (`String`);
* `director` — режисер (`String`);
* `year` — рік випуску (`int`);
* `minutes` — тривалість у хвилинах (`int`);
* `rating` — рейтинг (`double`).

Програма повинна:

1. прочитати дані з CSV-файлу;
2. перевірити коректність кожного запису;
3. не завершувати роботу через некоректний рядок;
4. визначити кількість коректних записів;
5. обчислити середній рейтинг;
6. визначити найдовший фільм;
7. визначити найстаріший рік;
8. сформувати звіт у текстовому файлі;
9. підтримувати параметри командного рядка `--help`, `--version`, `--input` та `--output`.

У тестових даних використано як коректні, так і некоректні записи, а також українські символи.

* створення директорії для вихідного файлу за потреби.

## 4 Інфраструктура проєкту

Для складання проєкту використовується **Maven**.

* Java 21;

Для всіх операційних систем використовується Java 21 та команда `verify`. Після успішної перевірки JAR-файли зберігаються як CI artifacts.
